# Bitcoin Diploma Redesign Documentation Index

## Purpose

This folder contains the planning, research, review, design, learning, assessment, certification, and implementation documents for the Bitcoin Diploma redesign.

The documents are intentionally separated so that:

- Review remains independent from Design.
- Design remains independent from Scope.
- Objectives remain independent from Assessment.
- Assessment remains independent from Certification.
- Scope remains independent from Learning Objectives.
- Research remains independent from conclusions.

This separation helps prevent assumptions, circular reasoning, duplicated content, and premature design decisions.

The package should be read as a decision-making system rather than a collection of isolated documents.

# System Relationship

The redesign follows the following logic:

```text
Review identifies problems.
Research validates assumptions.
Design defines principles and constraints.
Objectives define learner outcomes and competencies.
Assessment defines how learning is evaluated.
Certification defines future credential questions.
Scope defines the work required.
```

Later documents may reference earlier documents, but they should not replace them.

---

# Core Principles

1. Evidence before opinion.
2. Outcomes before content.
3. Assessment follows outcomes.
4. Certification follows assessment.
5. Design before implementation.
6. Educator needs matter.
7. Learner needs matter.
8. Community adaptability matters.
9. Standards matter.
10. Open-source publication matters.

# Current Working Direction

The following working direction appears across the package:

- in-person first;
- approximately 8-hour maximum completion pathway;
- 4-block structure under exploration: Problem / Fiat, Solution / Bitcoin, Action / Self-custody, and Custom / Bitcoin as Money;
- single Diploma with Custom and Advanced pathways;
- Core / Custom / Advanced content separation;
- increased practical learning;
- PPP methodology for practical skills;
- Educator Guide as a facilitation engine;
- Activity Bank as a core ecosystem component;
- standardized learning objectives;
- assessment framework in scope;
- certification design out of scope;
- localization preparation in scope;
- localization implementation out of scope.

These are working assumptions and should continue to be tested against research, learning outcomes, and implementation constraints.

# Active Source Of Truth

The active redesign package uses the following source-of-truth structure:

- `07_plan.md` owns the 4-block structure, planning direction, Custom / Bitcoin as Money model, and the candidate Advanced module title list.
- `05_objectives.md` owns learner outcomes, block-level objective framing, and Core / Custom / Advanced outcome boundaries.
- `02_scope.md` owns workstreams, milestones, deliverables, completion criteria, and public communication readiness.
- `09_activities.md` owns the Activity Bank structure and activity templates.
- `10_guide.md` owns Educator Guide structure and facilitation support.
- `13_spec.md` owns publication outputs, naming rules, and consistency checks.

Do not use `y_archive/` as a source of truth for the current redesign. It is historical only.

# Public Communication Outputs

The public communication layer is separate from the internal redesign package.

- `public/public_MFB-PRAGUE-BD.md` is the long-form public stakeholder brief.
